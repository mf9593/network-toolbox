# 使用帮助

网络工具箱是一款本地优先的 Android 网络调试工具。下面按「你可能遇到的具体问题」来组织，点开对应章节即可查看。

## 首次使用

### 这个应用能做什么？

它把日常查网络要用的东西收在一个 App 里，全部在本机完成，不需要注册账号：

- **看网络状态**：当前 WiFi、IP、网关、DNS、运营商、信号强度。
- **扫局域网**：把同一网段里的设备列出来，能看 IP、MAC、厂商、开放端口。
- **查 WiFi 密码**：从系统备份或配置文件里恢复已保存的 WiFi 密码。
- **连摄像头**：SADP、ONVIF、RTSP 三种方式发现和预览监控设备。
- **测网络**：Ping、端口扫描、DNS 查询、HTTP 调试、测速。
- **局域网传输**：不联网也能在同一 WiFi 下和另一台设备聊天、传文件。

### 第一次打开要先做什么？

建议按这个顺序：

1. **设置 → 主题配色**：先调成顺眼的配色（支持深色模式、跟随系统）。
2. **设置 → 权限管理**：把「附近的设备」「位置信息」「通知」这些该给的一次给完。
3. **无线** 页面确认已连上 WiFi。
4. **设备** 页面点「扫描」，看看能扫出哪些设备。

如果只是查 WiFi 密码，直接跳到下面的「WiFi 与密码」章节，不用先配权限。

### 为什么很多功能要求「位置信息」权限？

这是 Android 系统的规定，不是应用想拿你的位置：

- Android 6 起，**扫描附近 WiFi 列表**被归类为「可用于推断位置」的行为，必须给位置权限才放行。
- Android 13 起额外拆出「附近的设备 / 附近 WiFi 设备」权限，仍是同一个用途。

应用不会读取 GPS 坐标，也不会把位置或 WiFi 列表上传到任何服务器。给权限只是为了能列出 WiFi 和读取网络信息。

### 不给权限能用哪些功能？

- **不需要任何敏感权限**：Ping、端口扫描、DNS 查询、HTTP 调试、RTSP 预览、局域网聊天、设备扫描（部分信息会缺）。
- **需要位置 / 附近设备权限**：扫描附近 WiFi、读取当前 WiFi 的 SSID 和信号、导入 WiFi 备份后的部分解析。
- **需要所有文件访问**：应用内文件浏览器直接读取你选的备份文件、导入电视直播列表。不想给的话，每次用系统文件选择器也能选文件。

## 设备扫描

### 为什么扫描不到全部设备？

设备扫描不是只做 Ping，会同时用这些方式找：

- ARP 表 / NDP 表（局域网内已通信过的设备）
- ICMP Ping
- SSDP / mDNS（智能音箱、电视、打印机这类）
- NetBIOS（Windows 电脑）
- UDP 广播
- ONVIF / SADP（摄像头）
- HTTP 和常见服务端口探测

但下面这些情况扫不到是正常的：

- 路由器开了 **AP 隔离**（设备之间互相不可见）
- 设备防火墙禁止 ICMP 和端口探测
- 设备在**另一个网段**，当前只扫本机所在网段
- Android 系统限制读取 ARP / NDP 表（部分厂商系统）

想扫得更全，可以到 **设置 → 扫描设置** 把扫描速度调成「慢速」，探测超时更长，发现率更高，代价是慢一些。

### 设备名后面的分类标签是什么意思？

列表里每台设备右侧有两个小标签：

- 上面浅色的是 **IP 版本**（IPv4 / IPv6）。
- 下面是 **设备分类**：路由器、电脑、摄像头、手机、打印机、投屏、录像机、SADP 设备、UPnP、网页管理。

分类是根据发现该设备的协议和特征推断出来的。同一台设备可能同时支持多种协议，分类只取最能代表它的那一种。没有明确分类的设备（比如只被 Ping 到）不显示分类标签。

### 为什么设备名是「4C058C5YAG4CC1A」这种奇怪串？

这是设备自己在 UPnP / SSDP 广播里报的名字（序列号或 MAC 派生的标识），不是应用乱取的。这类设备通常没配置过主机名，厂家也没写友好名称。

点开设备详情可以看到所有协议各自报上来的名字，以及 MAC 和厂商信息，能帮你判断它到底是什么。

### 为什么 MAC 显示「未获取」？

Android 从 6.0 起就不让普通应用直接读 ARP 表了，部分厂商系统限制更严。应用会尽量从 ARP、NDP、SADP 和抓到的设备信息里补全，但**不保证每台都能拿到 MAC**。这是系统限制，不是应用的问题。

### 明明有这台设备，为什么标题不是我想要的？

设备标题按「协议优先级」决定，优先级可以在 **设置 → 标题优先级** 里调整。默认顺序大致是：

路由器 > NetBIOS > SADP > SSDP > mDNS > ARP 表 > UDP 广播 > HTTP > Ping > IPv6 > 端口探测 > ONVIF

意思是：如果 mDNS 报了个准确的主机名，HTTP 网页标题就盖不过它；反过来如果只有 HTTP 有名字，就用网页标题。觉得顺序不合适可以直接拖。

## WiFi 与密码

### 怎么导入 WiFi 数据？

- 打开底部 **工具** 页面
- 找到 **WiFi 与局域网** 分类
- 点击 **导入 WiFi 数据**
- 点击 **选择文件导入**

Android 11 及以上首次使用会提示授予「所有文件访问权限」。这个权限只用于让应用内文件浏览器读取你选择的备份文件；不想授权时也可以在提示框里改用系统文件选择器。

支持导入这些格式：

- 网络工具箱自己导出的 JSON / TXT
- 加密的旧版 title/content JSON
- MIUI、部分安卓手机的 .bak 备份
- vivo 设置备份
- ZIP 压缩包（包括 ZIP64 / MIUI 备份）
- wpa_supplicant 配置
- 文本化的 wifiConfig 数据库

选择文件后会显示导入结果。数量按 SSID + 密码统计，相同 SSID 的记录会合并。

### 导入后去哪里看密码？

两个地方都能看：

- **无线** 页面长按某个 WiFi，底部会列出这台 WiFi 已保存的全部密码，每个可以单独复制。
- **工具 → WiFi 与局域网 → 数据库查询**，能看到全部已导入的 WiFi 和每个 WiFi 的密码条数。

数据库页里：点或长按记录打开密码操作面板；支持复制、删除、撤销删除；标题栏的「清除空密码」会清掉空密码和开放网络的占位记录；搜索框可以按 SSID 或密码筛选。

### 怎么把密码导出保存？

**工具 → WiFi 与局域网 → 导出 WiFi 数据**，可以选：

- JSON 加密（推荐，需要密码才能再导入）
- JSON 明文
- TXT 文本

列表右侧显示「2 个密码」这类数量标签，标题栏有「全选 / 取消全选」。导出文件会存到你选的目录。

### 连 WiFi 提示缺少 CHANGE_NETWORK_STATE 权限怎么办？

如果提示里出现 **android.permission.CHANGE_NETWORK_STATE** 或 **android.permission.WRITE_SETTINGS**，说明系统在调用 WiFi 连接 API 时没在 APK 清单里找到该声明。

这是个**普通权限**，不需要用户手动点「允许」，但必须由安装包声明。**旧版 APK 缺这条声明，装最新版即可。** 应用不需要 WRITE_SETTINGS，系统提示的是「二者之一」，当前版本用的是 CHANGE_NETWORK_STATE。

装完还是连不上，逐项检查：

- 设置 → 应用 → 网络工具箱 → 权限
- **附近的设备 / 附近 WiFi 设备**：允许
- **位置信息**：允许，并选**精确位置**
- 系统**位置信息总开关**：开启
- 部分手机还要在定位设置里单独开「WiFi 扫描」

连接时系统可能弹确认框，需要点允许。少数厂商系统或工作配置会禁止应用直接连 WiFi，这种情况请用「系统 WiFi 设置」手动连。

### 点「打开 WiFi」没反应？

按 Android 版本分流处理：

- **Android 10 及以上**：应用调用系统的网络连接面板（下拉通知栏那个），由系统负责开关。
- **Android 9 及以下**：直接调用 WiFi 开关。
- 两种方式都失败时，会自动跳到系统的 WiFi 设置页让你手动开。

Android 10 起系统不再允许普通应用直接开关 WiFi，这是系统改动，只能走面板。

## 摄像头与流媒体

### ONVIF / SADP 搜不到摄像头？

- 确认手机和摄像头在**同一局域网**（跨网段扫不到）
- ONVIF 需要摄像头端**手动开启 ONVIF** 并设置账号密码（多数设备默认关闭）
- SADP 主要用于海康设备，设备要允许 SADP 发现
- 检查路由器是否开了 AP 隔离
- 有线网络和 WiFi 可能不在同一网段，注意当前用的是哪个

### SADP 和 ONVIF 有什么区别？

- **ONVIF** 是公开的行业标准，海康、大华、宇视、天地伟业等主流品牌都支持，能查设备信息、取 RTSP 地址。
- **SADP** 是海康的私有发现协议，只在海康及部分 OEM 设备上能用，主要用途是**给摄像头改 IP**、激活设备。

设备详情页会按它实际被哪个协议发现来显示对应入口：ONVIF 设备显示「ONVIF 调试」，SADP 设备显示「打开 SADP 调试」，不会混。

### RTSP / 电视直播播放失败怎么办？

播放内核为 libmpv / ExoPlayer 组合，支持：

- 标准 RTSP over TCP / UDP 单播
- HTTP MPEG-TS、HLS 等常见直播格式
- Basic / Digest 认证，多种视频编码
- Android 8.0 及以上；旧系统可用其他工具

播不了通常是这几类原因：

- 厂商私有 RTSP 封装
- 加密流，或需要特殊鉴权
- UDP 组播
- 编码手机不支持
- 直播源已失效 / 限流 / 禁止外部访问

可以试：

- 预览页切 TCP / UDP 换一种
- 确认地址里带了正确的用户名和密码
- 用 VLC 之类验证地址本身能不能播
- 换同频道的其他线路

部分摄像头只回 `a=rtpmap` 而不给 `a=fmtp` 参数集（缺 sprop-vps/sps/pps），播放器会直接报错，应用内置了兼容代理会自动补齐，不需要手动处理。

### 电视直播列表怎么用？

1. 把 `44023.txt` 放到内部存储根目录（`/storage/emulated/0/44023.txt`）。
2. 进「工具 → 摄像头与流媒体 → 电视直播」。
3. 页面自动加载列表，左侧选频道，右侧播放。
4. 文件在别的目录时，点左上角导入按钮选文件，或点文件夹按钮手动输入路径。
5. 列表格式：每行 `频道名,直播地址`；分类行写 `分类名,#genre#`。

提示找不到列表，通常是没给「所有文件访问权限」，或文件名 / 路径不对。也可以用系统文件选择器直接导入，不需要 root。

## 局域网聊天

### 聊天搜不到好友？

- 两台设备必须连**同一个局域网**
- 设备防火墙或路由器 AP 隔离会阻断发现
- 首次使用需要先设置昵称
- 要收后台消息提醒需要通知权限
- 好友发现依赖 UDP 广播 / 组播，部分企业网络会限制

还是搜不到，可以手动加好友：在好友页输入对方的 **IP 和端口**，直接连过去。连上后会互相学习昵称并自动存进好友列表。

### 聊天能传文件吗？

可以。会话页里可以选图片、文件，或者直接调相机拍一张发过去。接收方如果当时不在聊天页，消息和文件会自动收下并存好，再发通知提醒你。

文件传输用的是聊天端口 + 1 的 TCP 端口，所以两台设备之间能通 TCP 就能传，不需要额外的服务器。

### 聊天数据存在哪？

存在应用私有目录的本地数据库里，不会上传。卸载应用会一起删掉。

## 其他工具

### Ping 和端口扫描怎么用？

- **Ping**：输入 IP 或域名，可以设次数和间隔，会显示每次延迟和丢包统计。历史记录会保存。
- **端口扫描**：输入目标，可选常用端口组或自定义范围。扫描结果显示每个端口的状态和常见服务的说明。

两者都不需要 root。注意部分网络会屏蔽 ICMP，Ping 不通不代表设备不在。

### DNS 工具有哪些功能？

- 查询域名解析（A / AAAA / CNAME / MX / TXT 等）
- 指定 DNS 服务器查询
- 反向解析 IP 对应的域名

### HTTP 调试是做什么的？

发一个 HTTP 请求出去看原始响应，用来确认接口通不通、返回什么状态码和报文。适合调试路由器、摄像头、NAS 的 Web 接口。

### 怎么检查更新？

设置 → 关于与帮助 → 检查更新。

应用会请求 GitHub Releases 的最新版本。仓库要先发布 Release 才能返回版本；没有 Release 时会提示「仓库还没有发布 Release」。

## 数据与隐私

### 数据会被上传吗？

不会。WiFi 密码、聊天记录、设备信息、导入的文件全部只在你手机本地。只有在**你主动发起网络请求**时（比如检查更新、访问某个设备网页、播放直播源），应用才会访问对应的网络。

### 应用需要哪些权限，为什么要？

- **附近的设备 / 附近 WiFi**：扫描和连接附近 WiFi（Android 13+）
- **位置信息**：WiFi 扫描和部分连接 API 的硬性要求（不读取 GPS 坐标）
- **WiFi 状态**：读取当前 WiFi 信息
- **网络状态**：读取网络状态、发起连接
- **CHANGE_NETWORK_STATE**：普通权限，安装即授予，用于发起 WiFi 连接
- **存储 / 所有文件访问**：应用内文件浏览器读取你选的备份文件
- **相机**：扫一扫、拍照发图
- **通知**：局域网聊天的消息提醒

### 怎么清空数据？

- **清聊天**：聊天页面里删除会话，或到设置里清理。
- **清导入的 WiFi**：数据库查询页里逐条删除，或导出的形式先备份。
- **全清**：关于页面底部的「重置数据」，会清用户协议确认状态、WiFi 配置数据、局域网聊天数据库、应用设置。

## 还是解决不了？

请到 GitHub Issues 反馈，附上这几项能大幅提高定位速度：

- 应用版本（设置 → 关于软件里能看到）
- Android 版本和手机型号
- 具体操作步骤
- 错误提示的截图
- 如果是设备扫描 / 协议相关问题，可以在「运行日志」里导出对应协议的原始报文

**请勿上传真实的 WiFi 密码、聊天数据库或私人备份文件。**
