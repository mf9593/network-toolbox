## 1. 设备列表标题去掉【】分类前缀，改在 IPv4 下方显示分类标签

- 背景：设备标题被拼成「【ONVIF】摄像头」「【路由器】电信路由」这类形式。同一台设备在不同协议下前缀还不一样，标题又长又难认，分类信息其实更适合单独展示。
- 改动：
  - `app/src/main/java/com/networktool/app/util/LanScanManager.java`：ONVIF / SADP / SSDP 的 Windows 与 DLNA / 路由器品牌等标题生成全部去掉 `【】` 前缀。
  - `app/src/main/java/com/networktool/app/fragment/DeviceFragment.java`：域名命中的路由器分支同步去掉前缀。
  - `app/src/main/res/layout/item_device.xml`：IPv4 徽标所在位置改为纵向容器，新增 `categoryText` 分类标签。
  - `app/src/main/java/com/networktool/app/adapter/DeviceAdapter.java`：新增 `categoryLabel(DeviceInfo)` 按 `iconType` 推导分类文本（路由器 / 电脑 / 摄像头 / 手机 / 打印机 / 投屏 / 录像机 / SADP 设备 / UPnP / 网页管理），ARP、Ping 这类「发现途径」不显示标签。
  - `app/src/main/java/com/networktool/app/util/ThemeManager.java`：新增 `getBadgeSurfaceColor` / `getBadgeStrokeColor` / `getBadgeTextColor`。
- 关键实现：
  - 分类标签**不能**复用 `getChipSurfaceColor()`：它只掺 38/255（15%）主题色，铺在卡片上和卡片底色只差 8/3/5 色阶，肉眼看起来就是「没有背景色」——这是本轮返工的直接原因。
  - 改成三件套：底色掺 84（35%）、1dp 描边取 `getAccessibleThemeColor()`、文字浅色模式压暗（掺黑 210）/ 深色模式提亮（掺白 90）。

- 验证：
  - 编译通过；`zipalign -c -P 16 4` 通过；签名一致。
  - dex 内确认含新增分类文案（`SADP 设备`）。

## 6. Ping 工具：开始 Ping 后输入区收起、结果置顶

- 背景：整页是一个 `ScrollView`，从上到下依次是目标地址卡 → 快速选择 → 历史记录 → 结果卡。结果卡在最底部且 `minHeight=180dp`，点「开始 Ping」后要往下滑一大段才看得到输出；输出变长后还要一直跟着滑，查看很麻烦。
- 用户选择的方案：**输入区收起、结果置顶**（单页，不引入 Tab 栏）。
- 改动：
  - `app/src/main/res/layout/activity_ping.xml`：
    - `ScrollView` 增加 `android:id="@+id/scrollView"`。
    - 新增 `runningBar`（MaterialCardView，默认 `gone`）：左侧纵向放 `runningTargetText`（目标）与 `runningMetaText`（次数 / 间隔 / 包大小），右侧放 `paramsButton`（参数）与 `runningActionButton`（停止 / 再次 Ping），按钮间距 12dp。
    - 新增 `setupSection` 容器，把 `pingInputCard`、`quickSelectCard`、`historyLayout` 整块包起来，供运行态整体隐藏。`resultCard` 保持在容器之后。
  - `app/src/main/java/com/networktool/app/activity/tool/PingActivity.java`：
    - 新增字段与绑定：`scrollView` / `setupSection` / `runningBar` / `runningTargetText` / `runningMetaText` / `paramsButton` / `runningActionButton`，并给 `runningBar` 套 `ThemeManager.setupResultCard()`。
    - 新增 `onPingActionClicked()` / `stopPing()`：输入区和摘要条的两个按钮走同一条路径，避免两处状态不一致。
    - 新增 `enterRunningMode(host, count, interval, packetSize)` / `exitRunningMode()` / `scrollToTop()`。
    - 新增 `updatePingStateUi(boolean)`：统一刷新 `connectButton`（开始 Ping / 停止）与 `runningActionButton`（再次 Ping / 停止）文案。原来只更新前者。
    - `performPing()` 开始 Ping 时调用 `updatePingStateUi(true)` + `enterRunningMode(...)`；正常结束、手动停止、中断、异常四处收尾统一改调 `updatePingStateUi(false)`。
    - `applyThemeColors()` 补齐摘要条两个按钮与两个文本的主题色。
- 关键实现：
  - **不改数据结构，只改可见性**：`setupSection` 设为 `GONE` 后，`resultCard` 自然顶到 `runningBar` 下面，即屏幕最上方，不需要运行时重排 View。
  - 收起后「停止」按钮会跟着输入区一起消失，所以摘要条必须自带操作按钮，否则用户没地方停。
  - Ping 结束后**不自动恢复**输入区：结果继续留在屏幕上，符合「想看结果」的主诉求；要改参数点「参数」即可，Ping 不会被中断。
  - `scrollToTop()` 放在 `scrollView.post()` 里，等布局重排完再滚，否则滚的是收起前的高度。
  - 摘要条按钮间距用 `@dimen/space_3`（12dp），满足布局规范的 ≥12dp。
- 验证：
  - `sh gradlew compileDebugJavaWithJavac` 通过。
  - `sh gradlew clean assembleDebug` 通过；签名校验为 `c20a8284…a9e3f7`；`zipalign -c -P 16 4` 通过。
  - dex 内确认含新增文案（`次 · 间隔 `、`再次 Ping`）；`aapt2 dump xmltree res/layout/activity_ping.xml` 确认 `runningBar`、`setupSection`、`paramsButton`、`runningActionButton` 均在包内，且 `setupSection` 内含 pingInputCard / quickSelectCard / historyLayout。
  - 实机交互（开始 Ping 后是否收起、结果是否置顶、停止 / 参数 / 再次 Ping 是否正常）**待验证**。

## Ping 结果统计卡

- 背景：Ping 只给原始命令行输出，用户要自己数丢包和延迟；结束后没有汇总，中断时更看不出已经发了多少包。
- 改动：
  - `app/src/main/java/com/networktool/app/util/PingStatsParser.java`（新增）：解析 ping 输出，产出 `Stats`（sent/received/lost/lossPercent/min/avg/max/fromSummary）。
  - `app/src/main/res/layout/activity_ping.xml`：新增 `statsCard`（含 `statsSummaryText`、`statsSourceText`、`statsRow1`、`statsRow2`）。
  - `app/src/main/res/layout/item_ping_stat.xml`（新增）：单个指标块（label 上、value 下）。
  - `app/src/main/java/com/networktool/app/activity/tool/PingActivity.java`：`addStatTile()` / `showStats()` / `hideStats()` / `formatMs()`；正常结束、手动停止、异常三处均已接线。
- 关键实现：
  - 优先用 ping 自带的统计块（`N packets transmitted, M received` 或中文 `已发送 = N，已接收 = M`）。
  - 没有统计块（被中断）时按回包推算：最大 `icmp_seq` 视为已发送，含 `time=` 的行数视为已接收；这样手动停止也能显示丢包和延迟区间。
  - 推算出来的结果在 `statsSourceText` 上明确标「中断统计」，不伪装成系统统计。
- 验证：
  - `javac` 单独编译 `PingStatsParser`，用 5 组真实输出（正常跑完 / 中断 / 全不可达 / 部分不可达 / 空输出）跑过，结果全部正确。
  - `clean assembleDebug` 通过；签名 `c20a8284…a9e3f7`；`zipalign -c -P 16 4` 通过；`aapt2 dump resources` 确认 `id/statsCard`、`id/statsRow1`、`id/statsRow2`、`id/statLabel`、`id/statValue` 均在包内。

## 局域网聊天：实机实测发现并修复 3 个 bug（+1 个连带问题）

- 背景：两台真机（Redmi `192.168.1.159:5555` = 「111」UID 1934264738；M511CD = 「破晓」UID 1957334254，
  IP 在 `.157`/`.163`/`.173` 间随 DHCP 变动）装了 211 debug 包实测局域网聊天，发现：
  1. 同一条消息在库里存两行（`.159` 上 `_id 22/23` 内容与 `timestamp` 完全相同）。
  2. 好友列表里同一个人出现多条（「破晓」留下 `.157`/`.163`/`.173` 三行）。
  3. 对方发的图片消息渲染成一个**大黑方块**，只有图标轮廓。
- 改动文件：
  - `app/src/main/java/com/networktool/app/util/LanChatDatabase.java`
  - `app/src/main/java/com/networktool/app/util/LanChatManager.java`
  - `app/src/main/java/com/networktool/app/adapter/ChatMessageAdapter.java`
  - `app/src/main/res/drawable/ic_broken_image.xml`（重写）
- 关键实现：
  - **消息重复**：根因是顺序问题 —— `LanChatManager` 三处「先回调 `onMessageReceived` 再 `saveMessage`」，
    而 `LanChatRoomActivity` 回调里有 `if (!message.isSavedToDb()) 再存一次` 的兜底，回调时还没打标记就又存了一遍。
    现在统一改成**先落库、再 `setSavedToDb(true)`、最后回调**。
    另外在数据库层加了兜底：`DATABASE_VERSION 5 → 6`，
    - `onUpgrade` 先按 `(timestamp, sender, sender_ip, content)` 分组删重复（保留最小 `_id`），
      否则唯一索引建不起来；
    - 建 `UNIQUE INDEX idx_msg_unique ON messages(timestamp, sender, sender_ip, content)`；
    - `saveMessage()` 的 `db.insert()` 换成 `insertWithOnConflict(..., CONFLICT_IGNORE)`，命中唯一索引返回 -1 而不是抛异常。
  - **好友重复**：好友的身份是 uid 不是 IP。`addFriend()` 重写为「按 uid 收敛」：
    uid 为 0（发现阶段的占位行）时，若表里**唯一命中**同名的真实 uid，就认领成同一个人；
    然后把该 uid 在其它 IP 下的旧行删掉、把旧 IP 下的聊天记录迁到新 IP（排除 `chat_type='room'` 的群聊消息）、
    顺手清掉同 IP 下 `uid=0` 的占位行。新增 `dedupeFriendsByUid()` 在 `LanChatManager.start()` 里跑一次清历史脏数据。
  - **换 IP 后历史消息「消失」**（连带问题，实测中发现）：消息表是按 `peer_ip` 分组的，IP 一变旧记录就查不出来。
    这次一并解决：`addFriend` 迁移消息；`saveMessage()` 里自己发出去的消息 `uid` 为 0 时，
    按 `peer_ip` 从好友表补齐对方 uid，后续迁移才能认领这些行。
  - **图片黑框**：`ic_broken_image.xml` 原来是**实心黑**矢量（`fillColor="#000000"` 一整块），
    `imagePreview` 又是 200dp + `centerCrop`，于是整条消息显示成黑方块。
    重写成线性描边（相框 + 山形 + 斜杠）；`ChatMessageAdapter` 拆出 `showRealImage()` / `showImageMissing()`：
    占位态用 `CENTER_INSIDE` + 56dp 内边距 + 主题色 tint + `ThemeManager.getSurfaceColor()` 圆角底，
    真实图片恢复 `CENTER_CROP` 并清掉 tint/背景/内边距（避免 ViewHolder 复用串样式）。
- 验证（两台真机，ADB 实测）：
  - 消息去重：从「破晓」发 `dedup_test_1` / `e2e_final_test`，「111」发 `reply_from_159`，
    两端库里分别只有 1 行；`sqlite_master` 确认 `idx_msg_unique` 已建；升级时自动删掉了历史重复行（`_id 23` 消失）。
  - 好友去重：模拟把好友 IP 改成 `192.168.1.99` 再启动，好友表收敛回 `192.168.1.173|1957334254` 一行，
    `uid=0` 占位行被清掉，状态回到「在线」。
  - 图片占位：往库里插一条 `file_path` 指向不存在文件的 image 消息，气泡显示为浅色圆角块 + 居中线性图标（不再黑框）；
    指向真实 PNG 的那条正常铺满显示。
  - `clean assembleDebug` 通过；签名 `c20a8284…a9e3f7`；`zipalign -c -P 16 4` 通过；
    `versionCode 211 / versionName 2.1.1`。
