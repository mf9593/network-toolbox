- 根因：`clearButton` 用 `Widget.NetworkTool.Button.TextButton` 样式（透明底 + 主题色文字），Material3 TextButton 的文字色取 XML 静态 `?attr/colorPrimary`，不跟 `ThemeManager` 动态主题色；而页面的按钮主题应用循环只处理了 `scanButton` / `rtspPlayButton` / `rtspStopButton` 三个，漏了 `clearButton`。

## 按钮背景色跟随主题批量修复（ONVIF / 设备详情弹窗）

### 背景/问题
用户反馈 ONVIF 调试页「手动添加」按钮背景色奇怪、跟其他未选中按钮样式不统一。排查发现是 TonalButton 样式按钮的**背景色取 Material3 静态 `colorSecondaryContainer`，不跟 `ThemeManager` 动态主题色**导致的。顺带排查全项目同类问题。

### 根因与排查结论
`Widget.NetworkTool.Button.TonalButton` 继承 Material3 `Button.TonalButton`，背景默认取主题里静态的 `colorSecondaryContainer`。项目用 `ThemeManager` 动态主题色，换色后这个静态背景不变。修法统一是调 `ThemeManager.applyTonalButton(btn)`（淡主题底 `blendColorWithBase` + 主题色文字/图标）重刷。

逐个核对了全项目 TonalButton，结论：
- **已正确应用、无需改**：`ScanResultSheet` 的 copyButton、`WirelessFragment` 的 openWifiSettingsButton（`bottomsheet_wifi_fail`）都已调 `applyTonalButton`；各页 TextButton 样式按钮（透明底，只需文字色）也已设 `accentColor`。

### 改动文件
- `app/src/main/java/com/networktool/app/activity/tool/OnvifActivity.java`
- `app/src/main/java/com/networktool/app/fragment/DeviceFragment.java`

### 关键实现
1. **OnvifActivity `addManualButton`**：原先完全没应用主题。把它和 `scanButton` / `rtspStopButton` 一起归进 tonal 循环（`applyTonalButton`），`rtspPlayButton` 单独走 `applyPrimaryButton`（主操作实心）。这样「扫描 / 手动添加 / 停止」三个次要按钮样式统一，背景跟主题色。
2. **DeviceFragment 设备详情弹窗 `pingButton` / `portScanButton`**：原先只设了文字色没设背景色（`ping.setTextColor(accentColor)`），TonalButton 背景仍是静态色，跟旁边按钮不统一。改成 `ThemeManager.applyTonalButton(ping)` / `applyTonalButton(portScan)`，背景+文字一起跟主题色。同排的 copyIp / macQuery / share 是 TextButton（透明底），保持只设文字色。

### 验证方式与结果
- `sh gradlew assembleDebug` 通过；`adb -s emulator-5554 install -r` 成功。
- 背景色跟随效果待实机确认（按截图授权规则未默默截图）。

## 扫一扫连 WiFi 改走系统「添加网络」界面（消除双提示 + 应用归属）

### 背景/问题
扫一扫识别 WiFi 二维码后点「连接」，原来走应用内直连（`WifiConnector.connect()` → Android 10+ `WifiNetworkSuggestion`）。问题：会同时冒出**两套连接提示**——应用内 Toast + 系统建议网络确认通知；且 `WifiNetworkSuggestion` 是应用托管网络，系统 WLAN 列表会显示「通过 网络工具箱 连接」、不能改静态 IP。用户要求改成走系统界面、只保留一个提示。

### 改动文件
- `app/src/main/java/com/networktool/app/activity/settings/ScanActivity.java`

### 关键实现
改 `connectFromQr()`：
- **Android 10+**：改调 `WifiConnector.openSystemAddNetwork()` 拉起系统「添加网络」界面（`ACTION_WIFI_ADD_NETWORKS`，预填 SSID/密码）。系统界面点「保存」得到的是用户自己的普通网络——无应用归属标记、可改静态 IP，且只有系统那一个界面。系统界面拉不起时降级到 `ACTION_WIFI_SETTINGS` 手动添加。
- **Android 9 及以下**：保留原 `WifiConnector.connect()` 应用内直连。低版本走 legacy 旧 `WifiManager` API，加出来本来就是普通网络、不带归属标记，行为不变。

说明：`openSystemAddNetwork()` 标 `@RequiresApi(Q)`，已在 `Build.VERSION.SDK_INT >= Q` 分支内调用。所需 import（`Intent`/`Settings`/`Build`/`WifiConnector`）均已有。

### 数据存储（用户关注点，已核实）
- 扫码历史存 `filesDir/扫一扫.json`（JSON 文件，非数据库）。`saveScanHistory()` 写入前按 `title` 去重，**重复扫同一个码只保留最新一条**，不会堆重复记录。
- 扫到的 WiFi 自动存入 WiFi 密码库（`saveWifiToLibrary` → `WifiDataManager.addWifi`，内部按 SSID+密码去重）。
- 连接的 WiFi 本身不入应用数据库，交给系统管理。

### 验证方式与结果
- `sh gradlew assembleDebug` 通过；`adb -s emulator-5554 install -r` 成功。
- **实机扫码验证通过（2026-11-18，两次）**：
  - 第一次扫「NF-725」→ 系统保存界面正常弹出 → 点保存连上。`dumpsys wifi` 连接事件 `connectionNominator=NOMINATOR_MANUAL`、`networkCreator=CREATOR_USER`、`uid=1000`、`numConsecutiveConnectionFailure=0`。
  - 第二次扫「jwkj_5G」（系统里已存过的网）→ 连上。`connectionNominator=NOMINATOR_SAVED`、`networkCreator=CREATOR_USER`、`uid=1010`、`connectionResult=1`；`cmd wifi status` 显示 `Requesting package name: <none>`；全局 logcat 无任何 `WifiNetworkSuggestion`/`AddAppNetwork` 应用托管痕迹。
  - 两次均以**用户自己的普通系统网络**身份连接，**无「通过 网络工具箱 连接」归属标记**，可改静态 IP。达成目标：单一系统提示、无应用归属、持久普通网络。（注：`NOMINATOR_MANUAL` vs `SAVED` 只是目标网络此前是否已在系统存过，不影响「无应用归属」这一核心结果。）

## 修复 ONVIF 扫描结果卡片图标颜色不跟随主题

### 背景/问题
ONVIF 扫描结果列表卡片（`item_onvif_device.xml`）上的 4 个图标——设备类型图标（ic_videocam）+ 操作按钮（连接 ic_login / 播放 ic_play / 更多 ic_more_vert）——颜色不跟随 ThemeManager 动态主题色，切换主题色或深浅色时图标颜色不变。

### 改动文件
- `app/src/main/res/layout/item_onvif_device.xml`
- `app/src/main/java/com/networktool/app/adapter/OnvifDeviceAdapter.java`

### 关键实现
根因：4 个图标在布局里都用静态 `?attr/colorAccent`，这是静态主题属性，ThemeManager 切换的是动态主题色，不会自动跟着变。Adapter 里此前只给卡片背景 `setCardBackgroundColor` 套了主题色，**漏了图标 tint**。

修法：
1. 给布局里原本没有 id 的设备类型图标补 `android:id="@+id/deviceIcon"`（其余 3 个 ImageButton 已有 id）。
2. Adapter `ViewHolder` 新增 `ImageView deviceIcon` 字段 + `findViewById`，补 `ImageView`/`ColorStateList` import。
3. `onBindViewHolder` 里在套卡片背景色之后，统一取 `ThemeManager.getAccessibleThemeColor(context)`（自适应深浅色）生成 `ColorStateList`，对 4 个图标逐一 `setImageTintList()`，保证图标颜色始终与当前主题一致。

### 验证方式与结果
- `sh gradlew assembleDebug` 通过；`adb -s emulator-5554 install -r` 成功。
- **实机视觉确认（图标颜色随主题变色）待用户操作**——需进入 ONVIF 扫描结果列表查看，按截图授权规则未擅自截图；用户可自行切换主题色/深浅色确认图标是否跟随。

## 修复扫描设置「恢复默认」按钮文字下方被削

### 背景/问题
扫描设置弹窗（`dialog_scan_settings.xml`）里「标题来源优先级」行右侧的「恢复默认」小按钮（`btnResetPriority`），文字下方被削掉一部分。实机反馈「下面被削」。

### 改动文件
- `app/src/main/res/layout/dialog_scan_settings.xml`

### 关键实现
根因：`btnResetPriority` 是全项目唯一的「超小号 TextButton」——高 `32dp`、`minWidth=0dp`、左右 padding 仅 `8dp`，但父样式 `Widget.Material3.Button.TextButton` 自带 `insetTop/insetBottom ≈ 6dp` + 内部纵向 padding，把 32dp 内容区进一步压矮，12sp 文字垂直方向底部被削。

修法：清零 Material 默认的上下 inset 与纵向 padding，让文字用满 32dp 高度居中：
```xml
android:gravity="center"
android:insetTop="0dp"
android:insetBottom="0dp"
android:paddingTop="0dp"
android:paddingBottom="0dp"
```
左右 `paddingStart/End=@dimen/space_2`（8dp）保留不变。

### 验证方式与结果
- `sh gradlew assembleDebug` 通过；`adb -s emulator-5554 install -r` 成功。
- **实机确认修复（2026-11-18）**：用户打开扫描设置弹窗确认「恢复默认」文字显示正常、下方不再被削。清零 TextButton 默认上下 inset/padding、文字居中的修法生效。

### 补充：修复系统保存弹窗显示不出来
- **现象**：改走系统界面后实机发现，扫一扫点「连接」，系统「添加网络」页的保存确认弹窗显示不出来。
- **假阳性教训**：第一次用 NF-725 / jwkj_5G 验证时它们**系统里本来就存过**，系统直接按已存凭据重连、根本不需要保存框，所以看起来"成功"。用**全新网络**复测，保存弹窗依然出不来——证明问题没解决。
- **真正的根因**（重新逐行对比无线页 vs 扫一扫）：无线页在调 `openSystemAddNetwork()` **之前**多了一步 `WifiConnector.clearAllSuggestions(context)`，扫一扫漏了。若 App 残留 `WifiNetworkSuggestion` 托管建议，系统 `AddAppNetworksActivity` 处理新传入网络时保存确认框就渲染不出来；清掉建议、让系统回到干净状态才能正常弹框。之前误判为时序问题（加了 300ms 延迟），方向错了。
- **修法**：在扫一扫 Q+ 分支里、`openSystemAddNetwork()` 之前补 `WifiConnector.clearAllSuggestions(this)`，与无线页行为一致。300ms 延迟保留（避免弹窗未关时叠加启动）。
- **验证（2026-11-18）**：构建通过、装机成功。用户新增一个网络（jwkj_2.4G）扫码连接，**系统「添加网络」页保存框正常弹出**，点保存后连接成功。`dumpsys wifi` 连接事件 `connectionNominator=NOMINATOR_MANUAL`、`networkCreator=CREATOR_USER`、`uid=1000`、`connectionResult=1`；`cmd wifi status` 显示 `Requesting package name: <none>`。核心 bug（保存框出不来）修复确认有效。

### 背景/问题
应用已声明 `MANAGE_EXTERNAL_STORAGE`，权限管理页也有这一项，但工具页「系统原生设置」分类只有「电池优化」一个入口，缺一个直达系统「所有文件访问」开关的快捷方式。

### 改动文件
- `app/src/main/java/com/networktool/app/fragment/ToolsFragment.java`

### 关键实现
- 「系统原生设置」分类加 `所有文件访问` 条目（图标 `ic_folder`，已带 `?attr/colorOnSurfaceVariant` tint，深色自动跟随），仅 `Build.VERSION.SDK_INT >= R` 显示（低版本无此开关）。

### 验证方式与结果
